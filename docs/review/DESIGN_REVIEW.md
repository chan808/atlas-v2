# 설계 독립 검토 기록

기준일: 2026-10-13
대상: 초기 개인 사용 설계안 v0.1
검토 방식: 작성자와 다른 에이전트가 원문·설계·공식 출처를 읽기 전용으로 검토했다. 제품 코드 테스트나 실제 기기 실험이 아니다.

## 의도 충실도

초보/경험, 얕은/깊은 목표, AI 추천과 지속 변경, template fresh 선택, PC/Android, prepared offline, 후속 공유의 범위가 사용자 발언과 연결됨을 확인했다.

수정:
- '수학 후속 확정'을 '보류 가능'으로 바로잡았다.
- 템플릿 기능을 다시 선택 사항으로 만드는 '도입 여부' 문구를 수정했다. 규모·시점·효과는 검증 가설이다.
- 월 3만 원의 제안이 사용자 예산으로 굳어지지 않도록 제거했다.
- 첫 입력과 offline 로그아웃의 남은 선택은 Q8/Q9로 확인했다.

## 서비스 사실과 출처

기능이 없다고 단정하지 않고 직접 체험 여부와 rollout·언어·mobile 제한을 구분했다. Notebook 개인 채팅 이력의 직접 공식 출처를 추가했다. StudyFetch Visuals와 Mini Apps도 확인하여 경쟁 기능을 과소평가하지 않았다.

## UX·기록

수정:
- cursor와 관찰한 블록 노출·실제 재생 범위를 구분했다. 주의·이해의 증거로 환산하지 않는다.
- 단원 열기·배경 탭·audio seek 반례를 추가했다.
- 새 생성은 독립 job/branch이며 같은 template의 progress reset이 아니다.
- 로그아웃의 cache 정리와 원 owner 미전송 outbox 보관을 구분했다. 원 owner 재인증·다른 계정 차단의 검증을 추가했다.

## 기술

수정:
- 현재 attempt/lease token·작업 상태·대상 버전으로 결과 적용을 제한했다.
- 외부 중복 호출의 비용 가능성과 내부 결과 중복 적용을 구분했다.
- 파일 저장과 DB 참조의 부분 실패·orphan·누락·공동 restore를 추가했다.
- offline batch의 성공/중복/재시도/영구 거절/충돌을 구분했다. 인증 owner와 같은 ID 다른 payload의 의미를 명시했다.
- 출처 조회·구조/계산 검사·사람 검토의 actor/method/scope를 구분했다.

## 구현에서 반드시 검증할 항목

owner별 미전송 payload 보관·key lifecycle, 실제 목표폰 offline·잠금화면·seek, 모델/TTS의 내용·언어 품질, 배포 자원·무료 조건, 인증·backup/restore, 작업 중단·lease·취소·과금 기록.

표준 암호화 primitive가 있다는 사실은 key 관리와 전체 설계의 보안 검증을 대체하지 않는다. 재로그인 복원·로그아웃 key 제거·여러 탭·offline 재시작은 S4의 독립 검토 대상이다.

## 문서 정적 검사

최종 실행 결과는 마지막 검사 후 이 절에 기록한다. 검사 대상은 UTF-8, Markdown 내부 파일 참조, 코드 예시 JSON, 요구 추적의 기본 연결과 문서 상태 표현이다.

## 보강 뒤 재검토

UX와 기술 검토자가 수정 계약을 다시 읽었고 새로운 중대한 문서 충돌은 보고하지 않았다. 정상 앱 종료/offline 재시작과 명시적 로그아웃을 구분하는 마지막 경계도 반영했다. 암호화·기기·실 모델의 실행 검증 대기는 그대로 남긴다.


최종 문서 정적 검사 실행 결과:
- Markdown 문서 27개 UTF-8 읽기 성공
- 내부 파일 링크 47개 존재 확인
- 고유 외부 URL 96개 형식/목록 집계(모든 URL의 실시간 접근성을 이 검사에서 확인한 것은 아님)
- JSON 예시 1개 parse 성공
- PRD와 요구 추적의 R01–R15 연결 확인
- Markdown 표·code fence 기본 검사에서 오류 0개
- 오래된 Q2–Q9 진행 상태/예산 가정 검색 정리
- v1 git status --short 출력 없음: 기존 프로젝트 추적 파일 변경 없음

제품 코드·모델 호출·휴대폰 실험·배포 검증은 실행하지 않았다. 문서 검사의 통과를 해당 검사의 통과로 확대하지 않는다.
