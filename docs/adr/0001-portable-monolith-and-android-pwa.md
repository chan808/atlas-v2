# ADR 0001 — 이동 가능한 단일 서버와 Android 설치형 웹

상태: 제안. 사용자 요구는 확정됐지만 기술안의 최종 수용·실행 검증은 아직 없다.
기준일: 2026-10-13

## 근거

본인 PC+Android, offline 준비 자료, 소수 사용자, AWS 무료 자원 또는 개인 노트북, OpenAI API 우선과 필요 시 로컬 모델. 개발 기술 학습은 목표가 아니다.

## 추천

React·TypeScript 설치형 웹 + Spring Boot 단일 앱 + PostgreSQL을 초기 추천안으로 둔다. v1에서 확인한 저장·검증·실행 기반을 선별 재사용하는 이익과 AWS/개인 노트북 이동 가능성을 선택 이유로 삼는다. 기존 inquiry의 승인 중심 제품 흐름은 가져오지 않는다.

파일은 처음에는 접근이 통제된 서버 파일 저장으로 다루고 참조를 DB에 둔다. 실제 용량·백업·접근 필요가 확인되면 object storage로 바꿀 수 있게 한다. 서버 worker는 DB 작업 기록을 처리하며 별도 broker·microservice는 만들지 않는다.

Android PWA는 offline 준비 자료와 foreground sync가 기본이다. 잠금화면 재생·저장 유지의 실제 목표폰 검사를 통과해야 한다. iOS와 타인 협업은 후속이다.

## 대안

TypeScript 단일 앱은 개발환경을 줄일 수 있지만 저장·작업·권한 기반을 다시 확인해야 한다. native 앱은 미디어 제어가 필요할 때 재생 부분부터 검토한다. 특정 serverless 구성은 사용자가 이미 고려한 운영 환경보다 우선할 근거가 아직 없다.

## 실패와 되돌림

낮은 RAM·운영 불편·배포 검증에서 추천안을 반박할 수 있다. 실제 계정과 기기를 확인해 대안을 제안한다. 콘텐츠·개인 이벤트·API 의미를 플랫폼과 분리해 두고 자료를 export/backup 가능하게 한다. PWA 오디오가 필수 경험을 충족하지 못하면 파일 제공 또는 좁은 native 재생 계층으로 보완한다.

## 구현 전 확인

도구chain의 실제 버전·스키마 검증, 최소 배포 자원, 개인 서버 외부 접근 방식, 인증·소유권 방식, 목표폰 offline·음성 실험, 유한한 호출·retry 설정. 현재 이 ADR을 accepted로 표시하지 않는다.
