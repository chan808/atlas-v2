# 개발 전 설계 문서의 범위와 완료 기준

기준일: 2026-10-13 (Asia/Seoul)
현재: 초기 개인 사용 설계안 v0.1. 요구 발견·공식 자료 조사·독립 검토의 보강을 반영. 제품·환경 검증은 아직 실행하지 않았다.

## 문서 작성의 기준

사용자 직접 결정, 검증된 사실, 제안, 미정 선택, 사용으로 검증할 가설을 구분한다. 완벽하다는 표현이나 문서 양으로 준비 완료를 판단하지 않는다.

## 완료할 설계 묶음

| 문서 | 필요한 내용 | 완료를 판단할 근거 |
|---|---|---|
| 사용자 의도·결정 기록 | 원문, 실제 사용 장면, 우선순위, 조건, 미정 선택 | 중요한 선택의 근거가 사용자 발언 또는 명시된 위임에 연결됨 |
| 실제 서비스·학습 연구 조사 | 행동·제약·차용 원리·검증 한계 | 직접 출처와 확인일, 사실/주장/추론 구분 |
| PRD | 대상, 해결할 부담, 첫 가치 루프, 기능·비목표, 성공·축소 조건 | 사용자 장면을 수행하는 최소 범위와 장기 비전이 분리됨 |
| 사용자 흐름·화면 계약 | 시작, 본문, 어려움 조절, 복습·예습, 이동, 재개, 이력, 공유 | 정상·중단·오류·빈 상태에서 다음 행동이 설명됨 |
| 콘텐츠 계약 | AI·개발과 목표 외국어의 단위·표현·예제·시각·문항·음성 | 각 형식의 교육 목적과 지원·비지원 범위가 구체적임 |
| AI·출처·품질 계약 | 수집 범위, 주장-근거 연결, 검증, 재생성, 비용·지연, 실패 | 프롬프트가 없어도 허용 결과와 거부·대체 동작을 이해할 수 있음 |
| 데이터·API·상태 설계 | 원문, 콘텐츠·출처 버전, 위치, 학습·회상 이벤트, 연결, 공유 | 식별자·소유자·참조·수정·삭제·중복·동시성 정책이 설명됨 |
| 아키텍처와 기술 결정 | 저장·생성·렌더링·음성·작업·계정·배포의 최소 구조 | 제품 요구와 운영 부담을 근거로 선택. 기술 공부 목적의 구성 없음 |
| 보안·개인정보·공유 | 개인/공유 자료·진도 경계, 권한, 외부 전송, 파일·출처 처리 | 어떤 사용자가 무엇을 읽고 바꾸는지와 노출 방지 사례가 명확함 |
| 검증·수용 시나리오 | 콘텐츠 품질, UX, 저장·재개, 실패·권한, 실제 사용 | 각 요구와 이를 반박할 검사가 연결됨. 모델 호출 없는 CI와 실 모델 평가 구분 |
| 단계별 구현 계획 | 한 번에 보이는 행동, 의존성, 제외 범위, 검증·되돌림 | 기술 scaffold가 아니라 실제 사용자 결과로 단계를 끝냄 |
| 구현 인계·AGENTS | 읽는 순서, 결정 권위, 구현 가능한 첫 단계, 미정 사항, 금지된 추측 | 다른 세션이 이 대화 없이 첫 단계와 보류 사항을 이해함 |

현재 표의 모든 문서가 완성됐다는 뜻이 아니다. 사용자 선택에 의존하는 문서는 인터뷰가 진행되는 동안 초안으로만 작성한다.

## 설계 검토

1. 사용자 발언과 문서의 의미가 일치하는지 독립 검토한다.
2. 미래 목표가 초기 필수 범위로 바뀌었는지 검사한다.
3. 생성된 콘텐츠·열람·청취·회상·적용 기록을 혼동하는지 검사한다.
4. 원문·출처·내용 버전과 개인 기록·공유의 참조를 검사한다.
5. 내용 오류, 출처 충돌, 생성 중단, 중복 요청, 재생성 뒤 기록·댓글의 결과를 확인한다.
6. 남은 결정은 사용자에게 구체적인 선택과 추천으로 되돌린다.

## 현재 질문

- Q1 답변: AI·개발과 외국어 우선, 수학 등 보류 가능, 장기 타인 사용.
- Q2/Q3 답변: AI가 사용자 수준·목표를 반영한 추천을 제시하고 계속 조정. 언제든 방향·자료 변경. 선택적 템플릿과 새 생성.
- Q4/Q5 답변: 개인 PC·휴대폰, 준비한 이동 자료 offline, 새 생성 online.
- Q6/Q7 답변: Android, 비용은 주요 제약 아님, AWS/노트북·OpenAI·필요시 local LLM.
- Q8/Q9 답변: 주제·공개 링크·텍스트부터, 파일 후속. 미전송 기록은 원 owner 재로그인까지 보관.
- 실제 사례는 구현 시 콘텐츠 평가·사용 관찰에서 구체화한다. 사용자의 현재 수준을 제품 전역으로 고정하지 않는다.

## 기술 선택의 규칙

v1의 Spring Boot·React·PostgreSQL은 참고 가능한 구현 방법이다. v2 사용자 요구를 대신하지 않는다. 특정 스택·AI 공급자·배포·오프라인 방식은 확정하지 않았고, 비용·장치·데이터·지원 범위를 확인해 최소 구조를 제안한다. 프레임워크 확장이나 운영 기술 학습은 선택 이유가 될 수 없다.
