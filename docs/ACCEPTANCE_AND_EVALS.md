## 추가 반례

- 단원을 열고 블록 일부만 노출하거나 audio를 앞으로 seek하면 건너뛴 부분을 열람·재생 범위에 넣지 않는다. cursor와 coverage는 다르다.
- 템플릿이 있는 주제에서 새 생성을 선택하면 독립 작업/분기가 생성되고 템플릿 경로 재사용을 건너뛴다. 실패 재시도는 같은 작업을 유지한다.
- lease가 만료된 옛 worker의 결과, 취소 뒤 결과, 목표 변경 뒤 결과는 현재 경로에 잘못 적용되지 않는다.
- 파일 저장 뒤 DB 실패, DB 참조 뒤 파일 누락, 프로세스 종료·복원에서 준비 상태와 실제 파일의 정합성을 유지한다.
- offline eventId 재전송은 한 번 반영하고 다른 payload는 충돌이다. 영구 거절을 무한 retry하지 않는다.
- offline 로그아웃 뒤 저장된 미전송 payload는 해당 owner 복원 없이는 앱에서 읽거나 다른 계정으로 전송할 수 없다. key 제거·원 owner 재인증·복원·rotation/backup·다른 탭까지 검증한다.
- 출처 조회·구조 검사·사람 내용 검토가 구분되고 모델은 human-reviewed 표식을 생성하지 못한다.

## AI·콘텐츠 평가 묶음

첫 사례 후보(사용자 실제 사례로 교체 가능):
- AI: RAG의 목적과 한계, 초보와 구현 경험자의 차이
- 개발: timeout과 retry에서 결과가 모호한 사례
- 외국어: 상황별 표현·동의어·부자연스러운 번역·목표 언어 음성
- 선행 개념: AI 설명 중 필요한 기호·용어. 독립 수학 강좌 출시를 의미하지 않음

평가 항목: 원문 목표 충실도, 수준 적합성, 과도한 선수 요구, 내용·예제·출처 일치, 사실·가정 분리, 시각 목적과 계산 일치, 질문의 정답성·여러 정답, 음성의 발음·화면 독립성, 변경 후 기록 정합성.

## 검증의 종류

1. model-free CI: 스키마·참조·계산·버전·권한·중복·동기화·화면 흐름을 fixtures/fakes로 검사.
2. 제한된 실 모델 평가: 검토한 사례로 내용·근거·수준·지연·비용을 기록. 유료 호출은 일반 CI 조건이 아님.
3. 목표 기기 실험: Android offline·저장·재생·재연결의 실제 결과.
4. 개인 사용 관찰: 시작·재개 부담과 기존 서비스 대비 선호. 교육 효과 일반화의 증거 아님.

정확한 문장과 일치하는 테스트나 구현을 그대로 따라 쓰는 테스트보다, 요구를 깨뜨리는 반례를 우선한다. 실패를 통과시키기 위해 기대 결과를 약화하지 않는다.

## offline 장치 검사

다운로드 완료 후 앱 종료·비행기 모드·재시작, 카드 답변·음성 seek·잠금화면·다른 앱 전환·복귀, 연결 재개 후 두 번 동기화, 저장소 제거·공간 부족, 로그아웃·계정 변경을 검사한다.

브라우저 문서상 지원만 확인했으면 '실기기 미검증'으로 기록한다. Media Session 지원과 background 재생 지속을 같은 결과로 취급하지 않는다.

## 요구 추적 검토

R01–R15 모두 구현 단계·수용 사례와 연결한다. 초기 미포함인 R15는 후속으로 표시한다. 문서에만 있는 기능을 완료로 표시하지 않는다. 품질 수치와 지연·비용 목표는 예산·사용 사례 합의 후 값과 측정 방법을 함께 정한다.
