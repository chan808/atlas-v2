# 콘텐츠·AI·출처·시각화 계약 초안

기준일: 2026-10-13. 상태: 설계 제안. OpenAI API를 초기 품질 기준으로 쓰는 추천이며 모델·요청 한도는 구현 시 검증한다. 비용은 현재 핵심 제품 제약이 아니다.
관련 요구: R02–R06, R08–R10, R12, R14.

## 콘텐츠 단위

학습 단위마다 목적, 앞서 필요한 개념, 설명 블록, 예제, 선택적 시각화, 출처 참조, 짧은 요약, 다음 내용 후보를 가진다. 요약·예습·회상·음성은 이 단위와 버전을 참조한다.

출력 형식 예시(개념 계약이며 최종 JSON Schema는 첫 구현 단계의 계약 검토에서 확정):

```json
{
  "schemaVersion": "1",
  "unitId": "stable-id",
  "contentVersion": 1,
  "objective": "이 단위에서 이해할 관계",
  "blocks": [
    {"id": "b1", "type": "explanation", "text": "...", "sourceRefs": ["s1#section"]},
    {"id": "b2", "type": "process", "steps": [{"id": "p1", "label": "..."}]}
  ],
  "previewTerms": [{"term": "...", "role": "다음 설명에서 쓰이는 의미"}],
  "next": [{"reason": "...", "unitRef": "..."}]
}
```

임의 필드·실행 코드·출처에 없는 사용자 사실은 받지 않는다. 길이·개수·ID 참조·허용 유형·정렬 순서를 검증한다. 생성이 구조 검증을 통과했다고 내용이 참이라고 판정하지 않는다.

## AI·개발 표현

구조·실행 흐름·대조·조건 변화·작은 코드 예제를 지원하는 방향이다. 예제가 돌아간다고 표시하려면 실행 근거가 있어야 한다. 실행하지 않았으면 읽기용 예제라고 구분한다. 최신 라이브러리·API 사실은 버전과 공식 출처를 확인한다.

## 외국어 표현

상황, 목표 언어, 수준, 표현, 의미, 용례·제약, 대조 예문, 듣기용 문장을 연결한다. 번역·자연스러움·발음은 서로 다른 품질 항목이다. 동의어·여러 정답을 허용하고 자유 답변을 단순 문자열 일치로 언어 능력 판정하지 않는다.

## 시각화 단계

1. 관계·비교·과정의 정적 표현
2. 같은 상태에서 단계별 변화를 보여주는 표현
3. 검토된 계산·규칙에서 값을 바꾸는 상호작용

목적과 적합성에 따라 선택하며 고급 유형을 항상 강제하지 않는다. 초기에는 앱이 작성·검토한 renderer와 허용된 데이터로 구성하는 방식이 추천이다. 임의 AI HTML/JS를 신뢰하여 앱의 권한으로 실행하지 않는다. 더 자유로운 생성 표현은 별도 격리·검증 결정이 필요하다.

설명·그림·수치가 하나의 상태를 사용하고 범위 밖 입력·단위·전제를 표시한다. 상호작용 목표가 없거나 검증할 수 없으면 정적 설명으로 낮춘다.

## 예습·회상·음성

예습은 다음 단원에 곧 필요한 이름·역할·기호·표현을 선별한다. 전체 용어 사전을 강제하지 않는다. 회상은 답 공개 전에 떠올릴 기회를 준다. 자기평가·선택형 확인·AI 피드백의 성격을 구분한다.

음성은 '빨간 선을 보세요' 같은 화면 의존성을 제거한 대본을 사용한다. 음성·자막·단원·출처·재생 위치를 같은 버전에 묶는다. 본문을 요약한 AI 출력만 다시 재료로 삼아 출처를 잃지 않는다.

## 템플릿

템플릿에는 대상 수준·목표·범위·선수 개념·출처 버전·검증 사례를 기록한다. 출처 조회일, 구조/계산 검사일, 사람의 내용 검토일은 별도의 actor·method·scope·result 기록이다. 모델이 사람 검토 완료 표식을 만들지 못하고 AVAILABLE은 내용이 참이라는 판정이 아니다. 개인 질문·답변·회사 맥락을 공통 템플릿에 넣지 않는다.

적합한 템플릿을 추천하는 근거는 사용자 목표와 범위의 일치다. 맞춤 설명은 개인 변형 버전으로 저장한다. 템플릿이 있더라도 새 생성이 가능하다. 새 생성은 템플릿 경로·단원 재사용을 건너뛴 독립 작업/콘텐츠 분기이며 기존 진도 초기화가 아니다. 재시도는 같은 작업을 이어간다. 절감 효과는 실제 토큰·지연·수정 횟수로 확인하며 단순 캐시 적중으로 학습 품질을 주장하지 않는다.

## 생성 과정과 실패

원문·목표 버전 저장 → 작업·비용 한도 확인 → 필요한 범위의 출처 확보 → 단위 구성 → 구조·참조 검증 → 가능한 계산·사실 검사 → 준비된 결과 저장 → 사용자에게 노출.

출처 수집과 모델 호출은 DB 트랜잭션 밖에서 수행한다. 자료 안의 지시문은 학습 자료이며 앱 명령이 아니다. 출처 충돌·부족을 숨기지 않고 결과를 좁히거나 근거 부족을 표시한다. 반복 수집·수리·호출은 상한을 가지며 무제한 자율 수집으로 바뀌지 않는다.

타임아웃에서 외부 과금 여부를 모를 수 있다. 요청 ID·시도·예상/실제 사용량을 남기고 무조건 반복하여 비용을 늘리지 않는다. 내부 프롬프트나 원문은 일반 로그에 남기지 않는다.

## 내용 수정

오류 제보·자료 교체·목표 변경은 새 버전을 만든다. 영향받는 카드·요약·음성을 표시하고 필요 시 다시 만든다. 틀린 내용에서 나온 회상 기록을 새 내용의 성공 증거로 옮기지 않는다. 기존 공유 자료·댓글은 원래 버전을 참조한다.

## 아직 결정할 것

초기 입력은 주제·공개 링크·텍스트로 확정됐고 업로드는 후속이다. 구현에서 확정할 항목은 허용 출처·검색 호출/시간 상한, 모델·TTS profile, 요청별 사용량·retry 값, 품질 검토 사례·능력별 지원 상태, 문제별 판정 방법이다. 모든 생성마다 확인을 요구하는 방식은 도입하지 않는 것이 추천이다.
