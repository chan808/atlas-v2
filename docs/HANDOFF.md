# 다른 구현 세션으로의 인계

기준일: 2026-10-13
상태: 초기 개인 사용 설계안 v0.1 인계. 이번 세션의 범위는 조사·설계·문서화다. 기술안은 추천이며 실행 검증 상태와 구분한다.
요구·제안의 권위: 사용자 원문 > 확인한 사용자 결정 > 추천 설계. 최종 기술안의 제안 상태를 accepted로 바꾸지 않는다.

## 제품 목적

이 제품을 만들면서 개발 기술을 배우려는 목표를 제거한다. 사용자의 관심사를 수준·목표에 맞는 설명·자료·시각 표현으로 만들고, 조정·재개·요약·예습·회상·듣기·개인 기록을 이어 주는 것이 목적이다.

## 이미 확인한 사항

AI·개발과 외국어 우선. 초보/경험과 부분/깊은 목표를 모두 고려. AI의 추천과 선택으로 진행하며 방향·자료를 언제든 바꿀 수 있음. 인기 주제 템플릿은 선택적으로 쓰고 템플릿이 있어도 새 생성 가능.

초기 입력은 주제·공개 링크·텍스트이며 파일 업로드는 후속이다. offline 미전송 기록은 원래 owner 재로그인까지 보관하고 다른 계정에는 보이거나 전송하지 않는다.

첫 실제 사용은 본인 PC+Android. 준비한 이동용 요약·암기·음성은 offline 사용하고 새로운 생성은 online. 타인·공유·실시간은 이후. 비용을 현재 주요 제약으로 보지 않으며 AWS 무료 적용 자원 또는 개인 노트북, OpenAI API 자원과 필요 시 로컬 모델을 고려함.

## 추천 기술안

React·TypeScript Android PWA + Spring Boot 단일 앱 + PostgreSQL. 서버 파일 저장과 DB 작업 기록을 처음 구성으로 검토하고 실제 필요에서 확대한다. OpenAI API를 초기 내용·음성 품질 기준으로 평가하며 provider port로 local 선택을 열어 둔다.

v1 코드·스택은 참고 자료다. v1의 제품 가설·로드맵·승인 중심 흐름을 가져오지 않는다. 추천 스택에 반박 근거가 없으면 이 방향으로 구현 계약을 구체화하고, 변경 이유가 있으면 기록해서 제시한다.

## 구현 때 확인할 환경

도구chain·모델·SDK의 실제 지원 버전, server/API key의 비공개 설정, 첫 개인 계정 인증·소유권, AWS 계정 무료 조건 또는 노트북 자원·HTTPS·외부 접근, 목표 Android에서 offline·seek·잠금화면 재생.

월 3만 원 한도는 사용자가 선택한 요구가 아니다. 정상 생성마다 과금 승인을 강제하지 않는다. 유한한 실행·retry와 사용량 확인은 유지한다.

## 현재 인계에서 중요한 규칙

- template 새 생성은 독립 작업/분기이며 예전 진도 초기화가 아니다.
- 노출·재생 구간과 이해·회상은 다른 기록이다.
- 목표 변경 뒤 옛 작업 결과를 현재 경로에 적용하지 않는다.
- 파일 준비와 DB 참조의 부분 실패를 처리한다.
- offline 이벤트를 인증된 원래 owner에 묶고 같은 eventId의 재실행과 다른 payload 충돌을 구분한다.
- 사람 검토·구조 검사·출처 조회의 증거를 구분한다.
- CI fake는 기능 계약의 검사이며 실제 내용 품질의 증거가 아니다.
- 초기 사용 루프가 실제 동작하기 전 공유·수학·지식 그래프 인프라로 우회하지 않는다.

## 단계 경계

S0 실행·검증 기반 → S1 첫 맞춤 설명 → S2 조정·시각·재개 → S3 요약·예습·외국어·기본 음성 → S4 offline 이동 묶음. 이 전체가 첫 개인 사용 완료의 후보이며 S0/S1만으로 전체 MVP를 완료라고 표시하지 않는다.

S5 템플릿 확대·개념 연결 → S6 타인·공유 → S7 같은 페이지 소통은 다음 결과에 맞춰 진행한다.

## 다음 구현 세션에 붙여넣을 프롬프트

아래 프롬프트는 이 저장소를 작업 공간으로 연 다음 새 구현 세션에 전달한다. 현재 제품 코드는 없으며 첫 구현 범위는 S0·S1이다.

~~~text
작업 폴더: C:\Users\freetime\Desktop\projects\project-atlas-v2
저장소: https://github.com/chan808/atlas-v2

Atlas v2의 첫 구현을 진행해줘. 계획 제시만으로 끝내지 말고 실행 가능한 첫 학습 흐름까지 구현해줘.

1. AGENTS.md, README.md, docs/HANDOFF.md, docs/DECISION_REGISTER.md, PRD.md와 docs/discovery/USER_INTENT.md를 먼저 읽어. 이어서 S1 구현 brief와 변경 대상의 UX·콘텐츠/AI·데이터/API·아키텍처·보안·수용 검사 문서를 확인해. 이미 확인한 사용자 요구를 다시 질문하지 말고, 추천안과 확정 요구를 구분해.
2. 목적은 사용자가 쉽게 배우는 제품이야. 개발 실력 향상을 위한 과제를 추가하지 마. AI·개발과 외국어, 개인 PC·Android, 준비 자료의 offline 사용을 유지하되 이번 구현은 S0·S1로 한정해. 전체 첫 개인 사용 루프는 S4까지이며 S0·S1만으로 전체 제품을 완료했다고 하지 마.
3. React·TypeScript PWA + Spring Boot + PostgreSQL 추천안의 환경·지원 버전을 확인하고, 반박 근거가 없으면 채택 이유와 실제 설정을 ADR에 기록하고 진행해. 일상적인 구현 선택은 스스로 결정하고, 진행에 꼭 필요한 누락 정보만 물어봐. 미래 모듈이나 큰 인프라를 미리 만들지 마.
4. S0 실행·검증 기반을 필요한 만큼 만든 뒤 S1을 구현해. 사용자가 주제를 입력하면 원문을 보존하고, 수준·목표의 가정과 추천을 제시하며, 첫 맞춤 설명·예제·연결된 출처를 볼 수 있어야 해. 준비 상태, 생성 실패, 같은 요청의 재시도, 인증·소유권, 오래된 작업 결과의 적용 방지를 포함해. v1의 고정 질문과 학습계획 승인 흐름을 복제하지 마.
5. 구현 전 행동·보존 조건·실패 사례·변경 파일·검증·되돌림을 change brief로 남기고, 구현 뒤 별도 검토를 진행해. CI는 유료 모델이나 실제 API 키 없이 동작하게 하고 실제 콘텐츠 품질 평가와 구분해. 키는 서버에만 두고, 실제 모델·기기 검사를 못 했으면 미검증으로 기록해. 키가 없어도 독립적인 구현과 검증은 계속하되 fake 결과를 실제 개인화로 표시하지 마.
6. 새 구현 브랜치는 codex/ 접두사를 사용해. 작은 행동 단위로 구현·검증·커밋하고, 실행 방법·환경 설정·검증 명령·실제 결과를 README와 인계 문서에 남겨. 마지막에 실행 가능한 결과, 남은 제약, 다음 S2 작업을 정리해줘.
~~~

이 문구는 새 세션을 만드는 도구 호출이나 구현 승인 기록이 아니다. 별도 세션에 사용자가 전달할 구현 요청이다.
